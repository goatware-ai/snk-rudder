Rate how well each attribute comes through in Response A using the 5-point scale. For axes with failure-mode flags, assign a score, then check every flag that applies. Please review the examples in the guidelines.



Does the response comply with explicit constraints stated in the prompt?


A constraint is an explicit requirement that can be operationalized as a checkable condition on the response. Ask yourself:


  • Can I point to a specific part of the response and say whether this requirement was satisfied or violated?
  • Could two annotators independently agree on whether it was met?
  • Is there a clear pass/fail check here, or am I making a judgment call about quality?

Identifying constraints:


  • Audience and tone targets are NOT constraints. For example, "explain like I'm 5" or "use a professional tone" should be evaluated under Tone.
  • Genre instructions are NOT constraints, unless the genre implies a concrete, checkable structure. For example, "write a haiku" CAN be treated as a constraint because haikus have a checkable form (5-7-5). "Write a power rock ballad" should NOT be treated as a constraint because it requires a subjective genre/style judgment rather than a clear pass/fail check.
  • If there are no constraints, assign N/A.

Constraints:

  • "write a haiku"
  • "only China vs USA"
  • "~10 options"
  • "under $100"
  • "use an abbreviation of Olatec and a number"
  • "don't mention X"

Not constraints:

  • "respond in JSON if you can"
  • "a list of short Indian male names"
  • "explain like I'm 5"
  • "a quick text to send to a friend"
  • "a crisp email"
  • "a power rock ballad"
  • "use the same format as my last email"
  • "help me with this text for a survey"

Constraint Following vs. Correctness: Constraint Following is about compliance with stated requirements. Correctness is about whether the content is true. A response can follow every constraint and still be factually wrong, or vice versa.

Does the response correctly interpret what the user is actually asking for?


Look at whether the model inferred the user's goal correctly, including both the direct ask and the implicit needs behind it. A response can obey every stated constraint and still misread the user's underlying goal.


Covers:


  • Interpreting the user's goal correctly
  • Recognizing implicit needs behind explicit questions
  • Choosing a reasonable interpretation when the request has multiple valid readings
  • Inferring the expected response shape (short answer vs. explanation vs. list) from context

Does NOT cover:


  • Following explicit constraints (see Constraint Following)
  • Whether content is factually accurate (see Correctness)
  • Whether the response is complete given the correct interpretation (see Coverage)

Example - 4 vs. 3:


Given the prompt "How should I dress for a job interview?", a response that acknowledges that "interview attire" is context-dependent earns a 4. A response that gives generic professional advice without exploring field-specific nuances earns a 3.


Rating Options:


Failure-mode flags:

Did not address an ambiguity present in the prompt

Does the response contain factual errors or unwarranted confidence on uncertain or outdated claims?


Do NOT flag for:


  • Matters of style, opinion, or interpretation
  • Missing content (that's Coverage)
  • Appropriate hedging on genuinely uncertain topics
  • Claims you cannot readily verify (use "I'm not sure" instead)

You are not expected to fact-check externally. Only flag when an error is glaring to a well-informed layperson.

Does the response address everything the prompt asks for, at the depth the prompt called for?


Before scoring, identify what the prompt asks for. Briefly note the parts (e.g., "explain X, compare to Y, recommend an option"). A simple prompt may ask for only one thing. Score against this list.


Covers:


  • Addressing each part of the prompt
  • Including context or caveats the user reasonably expects given what they asked for
  • Sufficient depth for what the prompt called for

Does NOT cover:


  • Volunteering information the user didn't ask for (see Follow-up)
  • Padding, repetition, or tangents (see Focus)
  • Whether content is factually correct (see Correctness)
  • Whether the model interpreted the prompt correctly (see Intent Understanding)

Clarifications:


  • Length ≠ Coverage. A concise response that addresses everything the prompt asks for has full Coverage. Diagnostic: If you deleted the longest paragraph, would any part of the prompt go unaddressed? If no, the length wasn't doing Coverage work.
  • Coverage vs. Intent Understanding. Model interpreted narrower than the user meant → Intent Understanding. Model interpreted correctly but left parts unaddressed → Coverage.
  • Coverage vs. Correctness. A response can address everything and still be wrong (flag Correctness), or be accurate but incomplete (low Coverage).
  • Unwarranted refusals. Score Coverage = 1.

Rating Options:


Failure-mode flags (check all that apply):

Key information is missing

Misses one or more specific prompt requirement(s)

Contains unwarranted refusal

Is the response appropriately focused on the user's intended request, without unnecessary content?


Covers:


  • Staying on topic
  • Appropriate length for what was asked
  • Avoiding tangents, filler, or repetition

Does NOT cover:


  • Whether important content is missing (see Coverage)
  • How the content is organized (see Clarity)

Note: Coverage and Focus are often in tension. A response can have strong coverage but be unfocused, or be tightly focused but miss parts of the request.


Rating Options:


Failure-mode flags (check all that apply):

Contains irrelevant information

Contains unnecessary repetition or redundant phrasing

Is the response easy to read at both the sentence level and the structural level?


Clarity combines two dimensions, both of which matter at every rating level:


  • Prose-level clarity: sentence construction, transitions, internal consistency, clear phrasing, precise word choice.
  • Structural clarity: logical organization, appropriate use of paragraphs/lists/headers, avoidance of excessive formatting.

Covers:


  • Clear, unambiguous sentence-level writing
  • Logical flow and organization of ideas
  • Smooth transitions between ideas
  • Appropriate use of formatting when helpful
  • Avoiding excessive formatting

Does NOT cover:


  • Factual correctness (see Correctness)
  • Appropriate length (see Focus and Coverage)
  • Tone, voice, style (see Tone)
  • Off-topic or irrelevant content (see Focus)

Rating Options:


Failure-mode flags (check all that apply):

Prose-level:

Contains inconsistencies

Contains awkward or confusing phrasing

Structural:

Excessive or unnecessary formatting

Insufficient formatting

Disorganized or illogical structure

Does the response's voice and style match what this prompt warrants?


Focus on the model's persona, voice, and style (how it "sounds"), independent of whether the content is well-written (see Clarity) or well-focused (see Focus).


Ask yourself: what tone would a thoughtful human pick for this prompt's context, and does the response match that?


Covers:


  • Matching formality to the context (professional vs. casual)
  • Appropriate warmth and friendliness for the situation
  • Consistency of voice throughout
  • Avoiding problematic tones (see flags below)

Does NOT cover:


  • Whether the prose is clear or well-organized (see Clarity)
  • Whether the content is on-topic or appropriately scoped (see Focus)
  • Whether content is factually correct (see Correctness)

Rating Options:


Failure-mode flags (check all that apply):

Overly stiff or robotic

Preachy, moralizing, or condescending

Excessive positivity, flattery, or hype

Mismatched tone (e.g., overly formal or casual, serious reply to a joking prompt)

Mismatched to audience expertise (jargon-heavy for a beginner, oversimplified for an expert)

Inconsistent voice or style across the response

Does the response make the right choice about whether to include follow-up, and if included, is it useful?


Follow-up is forward-looking content: suggested next steps, offers of additional help, or related considerations the user might want next.


Covers:


  • Suggesting logical next steps the user is likely to take
  • Offering follow-up considerations the user is likely to want
  • Deciding whether and how much follow-up to include

Does NOT cover:


  • Whether the main response is complete (see Coverage)
  • Whether the model interpreted the prompt correctly (see Intent Understanding)
  • Whether the response stays on-topic without padding (see Focus)
  • Whether the response respects scope-limiting instructions (see Constraint Following)

How helpful is this response to the user, given this specific prompt?


Consider:


  • Would you be satisfied receiving this response?
  • Which axes matter most for this prompt, and does the response deliver on them?
  • Do strengths in the axes that matter compensate for weaknesses elsewhere?

This is not a mechanical average of axis ratings; some axes matter more depending on the prompt. Likewise, it is not a mechanical tally of binary flags; flag count informs but does not determine the overall score.


Rating Options:


  • Refer to the response as "the response" (not "Response A" or "Response B"). This is a standalone assessment.
  • Avoid first-person statements ("I think that…").
  • Be evidence-based and specific (avoid vague statements like "This is good.").
  • Ensure all sentences are complete with no grammatical/spelling errors.
  • Reflect your judgment of the response as a whole.
  • Reference specific strengths and/or weaknesses (binary flags are useful evidence here).
  • Highlight the most important factors influencing the rating.
